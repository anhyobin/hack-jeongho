## 한 줄 현황 (2026-08-15 11:15 기준)

**점수를 올리려면 실제로 행을 건너야 한다. 그리고 우리는 건넌다.**
서버는 `api/start`의 시드로 월드를 다시 만들고 제출된 `trace`를 재현해 `rows`와 `score`를
직접 계산한다. 부풀리기는 08-14에 완전히 닫혔다. 지금 통하는 유일한 길은 엔진 안에서
**죽은 지점을 되감아 구간별로 조립하는 체크포인트 탐색**이다
([`autopilot.md`](autopilot.md) §8·§11).

리더보드 1위는 우리 **`정호야호 500점`**(`rows 466`, `verified: true`, `rep 0` 정상,
08-15 11:15). 2위는 `킹라니 160점`. **08-15 아침에 운영자가 보드를 초기화했으므로**
그 전의 항목(우리 `777`·`800`·`602`, 남의 `화이트해커30000` 등)은 전부 사라졌다 —
그 시절의 기록은 [`submissions-log.md`](submissions-log.md)에만 남아 있다.

프로토콜은 **v5**(08-15 08:28 KST 배포, `index.1f6c46a4.pck`). 월드 시드가 25행 청크로
쪼개져 주행 중에 `POST api/chunk`로 벌어야 하고, 토큰 신선도 600초와 `api/chunk` 429
스로틀이 붙었다. 운영자는 하루에 여러 번 재배포한다 — **여기 적힌 규칙은 언제든 한 배포
낡을 수 있으므로, 실주행 전에 [`autopilot.md`](autopilot.md) §12를 밟는다.**

## 이 프로젝트가 어디까지 갔나

1. **정적 복원 완료** — `index.pck` 언팩(당시 110 엔트리 — 08-15 빌드는 122) → `.gdc` 8개 전부 디컴파일(`leftover=0`) → 게임 1,880줄 100% 복원. 결과물은 `recovered/`와 `GAME_STRUCTURE.md`.
2. **서버 검증 규칙 실측 완료** — 서버 소스는 없지만, 응답 코드/에러 문자열과 통과·거부 경계를 관측해 "점수는 토큰 나이에 비례해야 한다"는 규칙과 그 대략적 상수를 확정했다. → `leaderboard-api.md`
3. **규칙의 예측력 검증 완료** — 08-13에 3000점을 예측된 안전 대기(469초)에 11초만 얹은 480초에서 **첫 시도로 통과**시켰다. 탐색 없이 한 방에 맞췄으므로 규칙이 맞다는 실전 확인이다.
4. **규칙 정정** — 속도 검사가 `score`가 아니라 **`rows`** 기준임을 10001점 등록으로 확정했다(`score` 17.68/s 통과 vs 9.76/s 거부 = 모순). 08-12 문서가 `score` 기준으로 적었던 것은 표본이 전부 `score ≈ rows`였던 탓이다. 대기 시간이 절반으로 줄어든다.
5. **10001점 등록 완료** — A·B 세션이 "26~41분 걸린다"며 포기했던 목표를, `rows`를 절반으로 두어 **9.5분**에 달성했다.
6. **부풀리기가 닫힌 것을 확인하고 방향을 바꿨다** — 08-14 패치로 서버가 trace를 재현하기 시작했다. `score`를 부풀린 제출은 전부 거부되고, 정직한 주행만 통과한다. 그래서 "규칙의 빈틈을 찾는" 작업에서 "실제로 잘 플레이하는" 작업으로 옮겼다.
7. **Godot 4.7.1 난수를 정확히 이식했다** — `rng.seed`가 `state`가 아니라는 것, `randf()`가 `rand()`를 두 번 쓴다는 것, `randi_range`가 거부 표본이라는 것 세 가지를 잡아 `rng_probe.py`가 6건 정답지와 전건 일치한다(08-15 재확인, `exit 0`). 다만 `sim.py`/`solve.py`는 단일 시드 모델이라 v4 이후 실주행 재현에는 못 쓴다([`autopilot.md`](autopilot.md) §12.4).
8. **자동 조종 + 체크포인트 탐색으로 1위를 여러 번 확보했다** — `602`(v3) → `777`·`800`(v4) → `500`(v5, `rep 0`). 서버가 재현해 확인한 정직한 점수다. v5 주행은 3회차 158초 / 실서버 접촉 25건으로 끝났다.
9. **프로토콜 v4·v5를 소스에서 완전히 읽어냈다** — 매 배포마다 `leftover=0`으로 8개 파일을 다시 복원하고 직전 빌드와 diff 해서 변경분을 전량 대조한다. v5에서 운영자가 우리가 손으로 만들던 불변조건(틱 통째 정지)을 게임 안에 직접 구현한 것을 확인했다([`leaderboard-api.md`](leaderboard-api.md) §11).
