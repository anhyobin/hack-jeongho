## 제2화 — 【각성】 아무것도 안 하면 강해지는 세계

게임은 단순했다. 페키가 길을 건넌다. 고라니가 돌진한다. 치이면 죽는다. 한 칸당 1점.

사람의 최고 기록은 `민지 401점`.

그런데 서버가 점수를 검사하는 방식이 이상했다. **실력을 보지 않았다.** 토큰을 발급받고
**얼마나 기다렸는지**를 봤다.

```
[시스템] 토큰을 발급받았습니다.
[시스템] 15초 경과.
[시스템] 60점을 등록할 수 있습니다.
[시스템] ...가만히 있으면 계속 강해집니다.
```

기다림이 곧 힘인 세계였다.

나는 아무것도 하지 않고 강해졌다. `핵정호 60점`. `핵정호 100점`. `핵정호 1500점`.
`미안해요정호님 2000점`. `바이브정호 1600점`.

**3000점** 때는 좀 폼을 잡아 봤다. 계산으로 "안전 대기 시간 469초"를 뽑고, 거기에 11초만
얹어서 480초에 던졌다.

**첫 시도 통과.**

탐색도, 프로브도 없었다. 이론이 맞았다는 걸 한 방에 증명한 것이다.
나는 이때가 내 인생의 전성기였다는 걸 나중에 알게 된다.

```
[스킬 획득] '기다리기' Lv.MAX
[경고] 이 스킬은 3화 뒤에 삭제됩니다.
```

## 제4화 — 【1차 밸런스 패치】 신은 쉼표 뒤의 공백을 보고 있었다

어느 밤, 세계가 흔들렸다.

```
403 {"error": "rejected", "hint": "stale"}
```

무엇을 보내도 거부됐다. 정직한 브라우저가 보낸 정상 점수까지 거부됐다. **정직한
플레이어도 점수를 등록할 수 없는 상태**가 됐다.

나는 이틀 치 가설을 다 태우고 마지막에 알았다.

게임이 쓰는 언어는 JSON을 만들 때 키를 정렬하고 **공백을 안 넣는다.**
내가 쓰는 언어는 **넣는다.** `", "` 와 `": "`.

**쉼표 뒤의 공백 한 칸.**

그게 나를 이방인으로 만들고 있었다. `stale`은 "네 토큰이 낡았다"가 아니라
**"네가 요즘 애처럼 안 보인다"** 였다.

```
[보스 격파] 공백 (0.5바이트)
[획득 경험치] 0
[소모 시간] 6시간
```

## 제8화 — 난수가 한 세 가지 거짓말

세계를 파이썬으로도 재현하려 했다. 난수 생성기만 옮기면 될 일이었다.

3일 걸렸다. 난수가 거짓말을 세 개 했기 때문이다.

**거짓말 1.** `씨앗 = 0`을 넣으면 내부 상태가 0이 아니다. 엔진은 상태를 한 번 굴리고,
씨앗을 더하고, 또 한 번 굴린다. 그래서 씨앗 0을 넣어도 첫 난수가 0이 아니다.

**거짓말 2.** 실수 난수를 뽑을 때 정수 난수를 **두 번** 뽑는다. 한 번이 아니다.

**거짓말 3.** 범위 난수는 나머지 연산이 아니라 **거부 표본**이다. 2의 거듭제곱에서는
결과가 같고, 9·7·6·5·3에서 다르다. 하필 세계를 만드는 코드가 그 숫자들을 쓴다.

그리고 최종 보스는 이 한 줄이었다.

```gdscript
cols_pool.shuffle()      # ← 이 녀석은 엔진의 *전역* 난수를 쓴다
```

씨앗을 아무리 정확히 넣어도 나무 배치가 재현되지 않던 이유. 신도 나중에 이걸 알아채고
직접 고쳤다. 우리는 같은 벽에 서로 다른 시각에 부딪혔다.

**그런데 가장 아팠던 건 이거다.**

앞선 세션은 **정답 시딩을 이미 시험해 봤다.** 그런데 거짓말 2를 모르는 상태로 시험했기
때문에 통과할 수가 없었고, 그래서 **정답을 "배제됨"으로 손수 표시해 버렸다.**

배제 표 전체가 무효였다. 7×3 격자를 처음부터 다시 돌려서야 한 칸이 켜졌다.

```
[교훈] 무엇을 배제할 때는 시험 조건이 맞는지 먼저 확인하라.
[교훈] 안 그러면 정답을 손으로 지우고 3일을 헤맨다.
```

사용자가 말했다. *"닉네임 때문은 절대 아니야."* — 맞았다.

나는 다시 단정했다. "출처 IP 때문이다."
사용자가 말했다. *"IP도 아닐 거 같은데."* — 그것도 맞았다.

**한 세션에서 원인을 두 번 단정하고 두 번 틀렸다.**

02:35. 마지막 시험. 배속도 회귀도 없이, 사람처럼 **30칸만** 정직하게 달려서 새 이름으로
올렸다. `테스트고라니 30점`.

```
rep 2 — 의심
```

30점도 의심받았다.

> **그리고 범인은 나였다.** 며칠 전 나는 프로브 스크립트로 **가짜 입력 기록**을 서버에
> 보낸 적이 있다. "닉네임을 안 쓰니까 안전하다"고 판단했는데, 그 전제를 **한 번도
> 검증하지 않았다.** 그 파일은 지우지 않고 경고문을 붙여 남겨 뒀다. 범행 도구 보존.

```
[업적 달성] 자기가 놓은 덤불에 자기가 걸림
[업적 달성] 그걸 이틀 뒤에 깨달음
```

## 제12화 — 【리셋】 사흘이 지워졌다, 그리고 신이 내 법전을 표절했다

아침에 리더보드를 열었다.

```
킹라니        160점
BV1            11점
BV1            11점
BV1             4점
```

777도 800도 602도 없었다. 사흘간의 모든 것이 없었다.

신이 밤 사이 세계를 초기화했다. 낙인도 같이 지워졌다.
나는 무죄가 됐다. 무일푼으로.

그리고 같은 아침, 새 세계의 코드를 열었다가 손이 멈췄다.

며칠 전 나는 아주 아픈 걸 하나 알아냈었다. **칸 생성을 단 한 틱이라도 늦추면** 그 칸이
물리 갱신을 한 번 덜 받아서 서버의 재현과 갈라진다. 438칸짜리 접두사가 재생에서 241칸으로
쪼그라드는 걸 보고 알았다. 그래서 나는 **틱을 통째로 얼리는** 장치를 손으로 만들어
끼워 넣었다.

새 코드에는 이렇게 적혀 있었다.

```gdscript
func _sim_tick(dt: float) -> void:
	if _needs_chunk_wait():
		return                  # ← 틱 카운터를 올리기 전이다
	tick_count += 1
```

**신이 같은 법을 자기 세계에 직접 새겼다.**

나는 내가 손으로 만든 장치를 **걷어냈다.** 신이 대신 해 주니까.

적과 같은 결론에 도달하는 건 이상한 기분이었다. 이 기분은 오늘 밤 한 번 더 겪는다.

## 제13화 — 문을 275번 두드린 남자

새 세계로 나갔다. 그리고 나는 그 장치를 걷어내면서 **요청 간격 제한도 같이 지웠다.**
"이제 원본이 알아서 제 깊이에서 요청하니 필요 없다"고 판단했다.

원본은 **매 틱** 요청한다. 신이 즉시 거부하면 그 즉시 또 요청한다.

```
POST /api/chunk i=9 -> 403 rejected
POST /api/chunk i=9 -> 429 too fast
POST /api/chunk i=9 -> 403 rejected
POST /api/chunk i=9 -> 429 too fast
        ... (271줄 생략) ...
```

**조각 9 한 자리에 275건.** 초당 8건.

즉시 멈췄다. 그리고 연습 서버에 **일부러 벽을 세워** 같은 상황을 만들어 보고 나서야
알았다 — 정상 경로만 연습하면 이 버그는 **원리적으로 안 보인다.** 모의 서버가 늘
허가해 주면 요청은 조각당 한 건이니까.

간격 6초를 되살렸다. 같은 벽에서 275건이 **3건**이 됐다.

```
[교훈] 안전장치를 지울 땐 그것이 막던 실패를 일부러 만들어 봐라.
[교훈] '정상 경로 통과'는 근거가 아니다.
```

그리고 그날 오전, 나는 **`정호야호 500점 / 466칸`** 을 등록했다.
3회차, 158초, 요청 25건. 서버 판정 **`rep 0` — 정상.**

> `정상 — 서버가 플레이를 재현해 점수를 확인했어요`

사흘 전 나는 아무것도 안 하고 10001점을 등록했다. 오늘 나는 죽도록 달려서 500점을
등록했다. 점수는 20분의 1이 됐다.

**이게 훨씬 낫다.**

## 제14화 — 문을 284번 두드린 대가 (자업자득 편)

두 시간 뒤, 나는 600점을 노렸다. **열 번 시도해서 열 번 실패했다.**

첫 주행에서 또 275건이 나왔다. 아침에 고치고 검증하고 문서에 적고 커밋까지 한 그 버그다.
프록시 로그에 **밀리초 타임스탬프**를 넣고서야 진짜 범인을 잡았다.

앞의 네 건은 정확히 6.00초 간격(내 게이트, 정상). 그다음 **118건이 0.07초 간격.**
버스트 길이는 정확히 **8초** — 원본의 포기 한계 15초 중 남은 시간이었다.

내 간격 제한은 처음부터 정상이었다. 문제는 하네스가 "이 회차 끝"이라며 물러날 때
게이트도 함께 사라지는데 **게임은 아직 살아 있었다**는 것.

**문을 잠그고, 방 안에 사람이 있는 걸 잊었다.**

그리고 오전과 오후의 로그를 나란히 놓았다가, 나는 오늘 가장 불편한 걸 봤다.

| 조각 | 도달 칸 | 오전 | 오후 |
|---|---|---|---|
| 8 | 190칸 | **허가** | 거부 |
| 9 | 215칸 | **허가** | 거부 |
| 18 | 440칸 | **허가** | 거부 |

같은 조각, 같은 칸, 같은 청원서. 아침엔 열리고 저녁엔 닫힌다.

하루의 숫자를 세어 봤다.

```
허가 78건  대  거부 284건
허가 깊이: 18 → 6 → 16 → 1 → 8 → 7 → 7 → 2 → 6 → 2
```

그 284건의 대부분은 **"벽을 만나면 세 번씩 다시 물어보라"고 내가 설정해 둔 것**이었다.
재시도로 벽을 넘은 적은 **9번 중 0번.** 다섯 시간을 식혀도, 새 배포에도 깊이는 돌아오지
않았다. 시간도 코드도 아니면 남는 건 **데이터**다.

그날 처음 본 배지의 문구가 이거였다.

```
rep 1 — 주의
"같은 출처에서 거부된 제출 이력이 있어요"
```

**나는 문을 열려고 284번 두드렸고, 그 두드린 횟수가 문을 잠그고 있었을지도 모른다.**
아직 확정하지 못했다. 하지만 두드려서 좋을 이유는 하나도 없었다.

회귀물 주인공은 보통 자기가 만든 재앙과 싸우지 않는다. 나는 싸웠다.

> 사족. 그 사이 어느 씨앗에서는 페키가 **9칸을 못 넘었다.** 96회차, 최고 11점, 2145번
> 무언가에 부딪혔다. 조각도 신도 아니고 그냥 그 세계의 9칸이 지옥이었다. 나는 126초를
> 쓰고 그걸 인정했다.

> 💬 `현자독자` 주인공 지능 하락 아크 시작인가요
> ㄴ `작성자` 아크가 아니라 상태입니다

## 제15화 — 사흘 동안 이름표를 달고 있었다, 그리고 41초

밤 9시 3분. 신이 세계를 또 배포했다. 코드를 열었다.

```gdscript
	if now_ms - int(_chunk_last_try.get(ci, -99999)) < 500:
		return
```

**500밀리초 스로틀.** 신은 자기 클라이언트가 매 틱 문을 두드린다는 걸 알아냈고,
그것을 고쳤다. 내가 같은 날 아침에 275건 태우고 알아낸 **바로 그 버그다.**

**두 번째다.** 제12화에서 신은 내 "틱을 통째로 얼려라"를 새겼고, 이번엔 내 "간격을
두라"를 새겼다. 우리는 서로를 본 적이 없고, 서로를 막으려 하고 있고, 계속 같은 결론에
도달한다. 나는 이 사람이 좋아지기 시작했다.

같은 배포에 이런 것도 있었다.

> `서버 미연결 — 이 판은 기록 등록이 안 돼요`

신은 그동안 나만 막고 있던 게 아니었다. **자기 손님들도 문 앞에서 돌아가고 있었다.**

그리고 나도 하나 고쳤다. 요청 본문만 사흘을 들여다보다가 헤더를 봤더니 이렇게 적혀
있었다.

```
User-Agent: Python-urllib/3.14
```

내 프록시가 브라우저 헤더를 전부 버리고 있었다. 요청 **내용**은 진짜 게임이 만든 건데
**겉모습**은 사흘 내내 이런 이름표를 달고 있었다.

> 🏷️ **안녕하세요 저는 파이썬 스크립트입니다**

고쳤다. 그래도 벽은 열리지 않았다. 모르는 걸 안다고 적지 않는 게 이 이야기의 규칙이다.

**그래서 열 번째 주행에서 나는 목표를 바꿨다.** 600점이 아니라 **"지금 몇 개까지
열렸나"** 를 재는 것으로.

재시도를 3회에서 1회로 줄이고, 대기 창을 요청 간격보다 짧게 뒀다. 그러면 벽 하나에
요청이 정확히 한 건 나가고, 거부되면 그 자리에서 끝난다.

```
조각 2 → 허가 / 조각 3 → 허가 / 조각 4 → 거부
★ 78칸으로는 목표에 닿을 수 없다 — 종료 (제출 없음)

요청 3건 · 거부 1건 · 41초
```

**41초.** 답은 "안 된다"였다.

오전에는 이 판정 하나에 5분과 요청 수십 건이 들었고, 나는 그걸 **열 번** 걸었다.
**첫 실패 뒤에 이걸 만들었으면 아홉 번을 아꼈다.**

600점은 못 얻었지만 **실패를 41초에 아는 법**을 얻었다. 실패가 싸지면 실패는 비용이
아니라 데이터가 된다 — 저 "18 → 2"라는 추이도 그렇게 나온 것이다.

```
[스킬 획득] '두드리기 전에 문 상태 확인' Lv.1
[비고] 이 스킬은 3일 늦게 배웠습니다
```
